## 实现边界

原分支的 core 业务、资源定义、JSON、NBT、九个 payload 的业务字节与 API v2 均保留。
平台入口、注册、事件、重载和网络改接 NeoForge，映射改为 Mojang/Parchment。
可选 payload 使用对端通道能力检查；接收后的业务变化在逻辑主线程执行。
开发环境将 core 与适配器注册为同一个模组；成品为单个扁平合包 JAR。
正式构建仍要求两仓库干净、gitlink 一致、core 提交可从 origin 获取。

世界锚点在实体绘制前清理，实体后每个主帧推进一次 core。Iris 阴影 pass 不推进主帧，
GUI 使用独立预览会话。相机使用 1.21.1 的四元数向量契约。
受光不透明 mesh 在 Iris 消费 solid G-buffer 前提交；光影下延迟 mesh 在粒子后提交，
无光影延迟 mesh 在云、天气及 Fabulous 合成后提交。透明排序使用 GPU 的实际组合矩阵。
共享几何、静态 VBO、独立顶点格式 EBO、排序修订缓存及同帧回退保持原实现。

YSM 复用冻结参考的 NeoForge 2.6.5 符号和版本门禁，世界和预览仍使用当前公共锚点 API。
EMF 保留版本与 ABI 门禁。未支持的兼容版本在 Halo 内禁用捕获并回退，不要求加载器拒绝启动。

## OpenGL 对照诊断（2026-09-20）

第一轮 GL 状态恢复修复避免在 VAO 0 上绑定 EBO。`render-compat-01`
（SHA-256 `925d45a7671056dd1a1f37a13585c633cb4a0bfffac82312cff7c12ce426b97f`）
在 248 开光影时获用户确认：实体消失不再出现，EMF/YSM 预览正常。
219 的旧测试组合在光影关闭时仍记录 `Array object is not active`，不能视为彻底解决。

用户要求最后使用先前出错的简单隔离实例做有/无 Halo 对照，明确不使用复杂实例。
两组取自 `instances/client-21.1.219` 的同一世界、模组与配置快照；757 个共同输入文件
SHA-256 一致，仅 Halo 模组有无不同。环境与清单保存在缓存 `ab-219-render/`。
这属于错误复现对照，不是帧率或性能验收；视觉由用户操作确认。

新增 JVM 开关 `-Dhalo.renderDiagnostics=true`（默认关闭）：在提交前、状态捕获后、
绘制后和恢复后检查 GL 错误，记录主帧计数、世界/GUI、mesh/batch/primitive、
光影/pass、VAO/VBO/EBO/program。每类错误最多每 5 秒输出一次，摘要每 5 秒一次。
诊断会消费 GL 错误标志并增加同步开销，不用于性能压测。关闭时不执行 GL 查询。
本轮不修改 core，不处理用户明确排除的三角面遗留问题。

### 最后一轮结果与网络测试交付

| 对照组 | 用户视觉结果 | OpenGL debug 错误条数 |
| --- | --- | --- |
| 无 Halo | 未观察到实体消失 | 0 |
| Halo，仅加诊断、尚未修复缓存 | 实体消失复现 | 6,139 |
| Halo，修复缓存 | 实体与预览正常 | 0，Halo errorFlags=0 |

这些是短时会话的原始错误计数，不是相同持续时间的性能比较。三组日志均为光影关闭；
本轮未执行光影开关复测。证据保存在 `ab-219-render/evidence/`。

根因证据：`HaloRenderState.close()` 直接恢复 VAO，但批次提交会更新
`BufferUploader.lastImmediateBuffer`。随后 vanilla 若再次用相同缓冲，就跳过绑定，
在已恢复的其他 VAO（可为 0）上执行上传/绘制。修复在恢复前调用
`BufferUploader.invalidate()`，使后续实际重新绑定。该调用不修改 GL 状态，
219/248 均支持，无 core 修改。日志和用户复测结果支持此修复。

网络候选 `network-test-01`：`2.4.1+adapter.1.dev`，248 构建，SHA-256
`4a52cc98d146b4bf676608be688cf17f4b26646620962eb0556de0e858b25852`。
219/248 均通过构建及 125 平台测试，无失败或跳过；同一 JAR 在两版普通专用服
启动并完成基础命令、保存退出。248 初次自动脚本在召唤后立即查询，实体尚未进入
可查询的区段而报 Invalid entity selector；为测试脚本加上跨 tick 等待后复测通过，
未为此修改生产代码。219 客户端获上述签收；新增修复的 248 客户端视觉仍未重测。

core 维持 2.4.1 / 295bc579ab8d63e6dba5642ebb9e889516e90105，干净。
Halo 仍在 1.21.1-neoforge 未提交工作树（基于 d09d864），未推送/tag/Release。
用户接手网络测试，其他尚未签收的发布门槛维持待测。
