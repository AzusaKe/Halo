## 维护者确认的时间与验收规则（2026-10-26）

普通回放和离线导出都使用**录像源时间**推进动画、过渡和物理。
1 秒录像按 2× 导出为 0.5 秒视频时，Halo 推进 1 秒；实际机器渲染耗时不参与计算。
这替代早期 analyze 文档中“导出按输出经过时间推进表现”的默认策略。
输出帧编号/FPS 仍用于标识采样，预热、加载等待和同帧多视角不能重复推进模拟。

验收要求速率正确，不要求逐帧复现原游玩位置或不同 FPS 的轨迹完全重合。
seek 恢复佩戴、相位和 UI，清除未来惯性并从目标锚点重建；首轮不保存物理轨迹或检查点。

## API 与职责

`network.azusake.halo.api.v2.replay.HaloReplayApi` 是新增的中立入口：

- `openRecording(backendId, listener)` 返回可关闭的录制会话；`snapshot()` 返回完整不可变快照。
- `openPlayback(backendId)` 返回独占回放会话；`restore(snapshot, sourceNanos, epoch)` 原子替换，
  `apply(event, sourceNanos, epoch)` 按容器时间应用事件，`frame(time)` 在 tick/网络应用前设置时间。
- `mode(PLAYBACK/EXPORT_PREPARING/EXPORTING)` 控制 UI 展示；关闭清理回放状态，普通连接按自身流程重建。
- 所有调用属于客户端线程；后端 ID 为小写 `namespace:path`。无宿主时返回空 Optional。
  多个录制观察者可以共存；同 ID 重复订阅拒绝，回放控制器只允许一个。
- 回放开启会结束录制观察，防止递归录制。断开使会话失效；世界切换保持会话，由全量快照建立边界。

完整快照包含 UUID→定义表、表现实例（包括摘除后的关闭动画）及权杖状态。
表现实例使用相对年龄、相对过渡时间、冻结相位、活动/隐藏事实和关闭起点分组值。
快照序号是增量水位；空快照同样必须写入。恢复不要求实体或定义已经可用。
普通健康卸载不录为摘除；恢复后实体按 UUID 关联，不使用持久化的数字实体 ID。

core 实现规则和状态，不依赖 Minecraft、Fabric、Mixin 或第三方类；公开值仅依赖 JDK 和 API v2。
Halo `replay/` 负责共享 payload、宿主绑定、UI 和写回隔离；各 `compat/` 后端负责外部 API、容器时间/记录采集和 hook。
索引排序、快照选择及顺序/跳转恢复由 core 的 `ReplayTimeline` 统一实现。
旧 API v2 和 `ClientPort` 签名保留。

## 录像 schema 1

共享内层通道为 `halo:replay`，UTF-8 JSON 封装 `schema`、轨道 UUID、记录种类及数据。
种类为 `snapshot`、`wearer`、`ui`、`reset`，两个录制器共用 `ReplayPayloadCodec`。
codec 不写录像绝对时间，使用外层容器时间；年龄及过渡进度为相对值。
schema 独立于 API v2 命名空间；未知 schema 明确报错，不能当成空佩戴。
录像只保存定义标识与状态，不内嵌资源包；对照实验需固定定义、配置、模型和纹理。

## 首轮人工验收步骤

使用 1.21.1 Fabric，替换旧 Halo 为本次 alpha 测试 JAR；每次只安装一个录制模组。
先固定资源包和配置，使用能明显看到旋转/启动/关闭的内置光环，例如 `halo:ring_default`。

1. 新录制：已有佩戴后开始录制；ReplayMod 可先佩戴、退出保存后重新进入世界以产生新的自动录像。
2. 录制约 15 秒：第三人称移动和转头，摘除再佩戴，打开权杖后用 ESC 关闭，再打开并按关闭按钮。
3. 打开新录像：检查起点已有佩戴；暂停不继续旋转/跟随；0.5×/1×/2× 的速度按录像倍速变化。
4. 前后拖动到佩戴、摘除和 UI 开关前后。ReplayMod 分别检查 Full 和 Quick；旧数字实体 ID 不应影响目标关联。
5. 从非零时间开始分别导出 30/60 FPS，包含 UI 开关和佩戴变化；慢速实际渲染不能让动画加速。
   再检查 2× 关键帧：1 秒源动作输出为 0.5 秒，光环也推进 1 秒。导出不打开 Halo 交互界面或等待其关闭。
6. 取消后重新导出、关闭并重新打开录像，确认时间和界面不残留。

先反馈录像文件、加载器/模组版本、失败步骤、期望/实际结果和 `latest.log`。
这轮基础用例通过后再测来源优先级回退、非玩家卸载返回、暂停/裁剪/拆分、分段快照及多视图/光影。

ReplayMod 后处理在 `compat/replaymod` 的可选边界 hook 中接入：完整原始流提供裁剪前基线，
`SquashFilter` 折叠 Halo 事件并在裁剪结束/拆分起点写入按原始经过时间推进后的完整快照。
语义折叠在 core 的 `ReplayStateAccumulator`，库对象和包重写仍在 compat；真实 marker 工作流尚待人工验证。
