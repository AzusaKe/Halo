# 半透明 mesh 三角面排序修复

## 问题与契约

2026-09-20 用户报告 `mesh_mask_demo` 在斜视时出现突兀三角面，所有 core 版本均可复现。
检查发现共用 `MeshIndexWriter` 只按三角形中心的 view-Z 排序。即使两个面不相交，
它们在屏幕重叠区域的远近也可能与中心深度相反；标准 alpha 混合有顺序依赖，因而
产生三角形轮廓的颜色接缝。半透明路径已经关闭深度写入，不能靠打开深度写入修正混合。

core 新增完整视图入口 `prepareBackToFrontView(float[16], boolean perspective)`：
输入为绘制实际使用的 affine local-to-view，不含投影。对投影有重叠的三角形裁剪交集，
比较交集顶点处的深度（透视采用线性插值的倒数深度），建立远面先于近面的约束，再做稳定拓扑排序。
与旧排序无冲突时按旧顺序优先。矩阵全部系数和投影类别进入缓存，避免平移后误复用。

只改变索引顺序；模型、UV、法线、alpha mask、深度写入和双面规则不变。无 JSON、存档、
网络或 API v2 变更。旧 writer 方法仍保留原顺序；其他适配器必须显式接入新方法，
不能仅更新 core 指针就宣称修复。GPU 和 CPU 回退必须使用相同完整视图及投影类型。

## 验证

- core fixture 来自内置 `mesh_demo.obj`，288 个三角形。
- 8 个方向 × 2 个距离 × 4 个高度（含下方与掠射）× 透视/正交，共 128 个视图，
  独立射线与三角形相交算法检查实际可见重叠：原中心排序 2,528 次倒置，新排序 0 次。
  采样是自动几何证据，不等于游戏截图验收。
- 覆盖完整矩阵缓存、横向平移、投影切换、旧/新策略切换、镜像绕序、展开顶点流及 CPU 回退。
- 覆盖退化变换、穿过眼平面、相交与预算回退时保留全部三角形。
- core 完整构建及冻结旧调用方兼容检查通过；26.2 NeoForge 联合构建通过。
- 1.20.1 Fabric 主线在隔离目录 `F:/codex-cache/halo-mesh-transparency-1.20.1` 接入，联合构建通过。
- Java 17 独立微基准：288 面模型、每轮 3,000 个变化视图，预热后平均约 0.47–0.49 ms/次。
  这是排序 CPU 成本，不是整帧耗时或游戏 FPS；多个动画实例下成本会累积，需要游戏压测。
- 用户随后实测确认：原报告场景的问题已无法复现，当前场景 bug 修复验收通过。
  此确认限于用户实测场景；本次反馈未补充渲染后端、光影及兼容模组组合，
  不据此推定原生 OpenGL/Vulkan、Iris/EMF/LabPBR 各组合或 1.20.1 Fabric 均已视觉验收。
- 游戏性能压测尚未执行。

第一次同时启动 core 与联合构建导致二者竞争 core 测试输出目录；core 独立构建通过，
联合构建报测试结果文件丢失。等待退出后单独重跑联合构建通过，非源码测试失败。

## 边界及待验收

此修复不是 OIT。真正相交/循环遮挡的面无法总靠重排解决；存在循环时保留完整旧顺序。
穿过眼平面的三角形保留近似次序；超过每次 262,144 候选对预算时也回退旧排序。
跨 mesh 实例、与 Minecraft 世界透明物体的全局排序没有改变。每个 writer 懒分配并复用
工作区，但新排序增加 CPU 工作，游戏规模下的性能尚未验收。

用户已明确本次范围：修复当前场景的单 mesh 透明面排序；暂不覆盖交错、跨 mesh，
也不引入更高开销且需要大改 core 接口或渲染管线的方案。这些限制作为已知边界保留，
不作为当前场景 bug 仍未修复的理由，也不列为本次必须补齐的功能。

后续收尾可检查常用模型、物品栏预览、重载和代表性实例数下的性能，再逐版本接入并
记录对应平台的实际验证。冻结分支不变；已通过的用户原场景无需反复要求重验，
除非后续源码变化影响该路径。
