# 26.2 Fabric EMF cape capture correction — adapter.2

## Failure and evidence

Halo `5a8aff882ba6de0ef3bfc9558622c109fe1b9deb` / `2.4.1+adapter.1` could lose EMF idle, ladder and landing movement in third person and the inventory while swimming/elytra orientation still followed. The user reproduced with shaders enabled or disabled and with Alex or Steve skins; flash 1.3.0 worked in the same environment.

A complete copy of the user's mods, config, packs and world did not reproduce with the offline Dev1 account. All 11 mod-directory files matched by SHA-256. Instrumenting the original account established the difference: a `PlayerCapeModel` named head arrived before the body `PlayerModel` head. The cape head had zero animated pivot, was accepted into the first-capture slot, and the later animated body head was skipped. The GUI scope likewise accepted the cape first. This is model identity selection, not a diagnosis of the user's skin texture features.

Original diagnostic evidence is preserved locally in `F:/codex-cache/halo-262-emf-original-probe/reproduced-original.log` (20:38:12, frames 1800/1860) and `diagnostic.patch`. Diagnostics are not included in the fix.

## Correction

- At `LivingEntityRenderer.submit` entry, bind the actual renderer body model to the copied entity snapshot used by deferred features. This follows the frozen flash implementation's base-model identity rule without adding a global model map.
- Vanilla and EMF capture require that same model and its actual head part. Cape and armor heads cannot consume or replace the body capture regardless of submission order.
- Apply the identity gate before world/preview capture selection. Preserve the existing per-frame duplicate and Iris shadow rules.
- Invisible preview pose-only capture remains allowed only for its explicitly supplied head, without relying on a deferred draw context.
- Core is unchanged at `295bc579ab8d63e6dba5642ebb9e889516e90105`; no schema, NBT, network or API v2 changes, and no changes to lower-version adapters or frozen flash branches.

## Validation

- `./gradlew.bat build --console=plain`: passed, 128 adapter tests, existing core checks, merged JAR/provenance and legacy API v2 checks. Logs: `F:/codex-cache/halo-262-emf-cape-build.log`.
- Three new regressions exercise cape and armor draws before/after the base model, preview first-capture selection, and rejection of a shadow capture. They construct the real 26.2 `PlayerCapeModel` subclass, not a string-based type mock.
- Original production-loader instance: Minecraft 26.2, Fabric Loader 0.19.3, EMF 3.3.5, ETF 7.2.1, FA+Player 1.1 and the user's other packs/mods. User confirmed the original failure was fixed with `2.4.1+adapter.2.dev` and authorized release. The client exited normally at 20:44:52; acceptance log is stored in `F:/codex-cache/halo-262-emf-original-probe/fixed-original.log`.
- The broader Vulkan, multiplayer and LabPBR matrix remains the adapter.1 baseline in [the migration record](26.2-fabric-migration.md); it was not repeated for this model-selection-only correction. Invisible preview is preserved in code but was not separately visually re-tested during this fix.

Version: `2.4.1+adapter.2`. Tag: `v2.4.1-fabric-26.2-adapter.2`. Existing adapter.1 tags remain unchanged. The tag points to the exact Halo revision; its bundled provenance records the Halo/core SHA values. The release workflow builds and attaches the final JAR and sources.
