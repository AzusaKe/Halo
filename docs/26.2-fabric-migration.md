## Adapter contracts

ResourceLoader v1 reloads apply after the preparation barrier on the game executor.
Client definitions and prepared visual resources publish before the definition report is sent.
The core API, schema, storage and wire format are unchanged.

World collection samples one immutable core output per main-camera frame. Solid and late
stages consume that output without advancing physics again. Native world/PIP projections
use reverse-Z. The late stage follows the frame graph before camera teardown/Iris composites.

26.2 ModelFeatureRenderer.prepareModel brackets the deferred real model draw, with a copied
entity identity. PIP capture brackets both collection and feature execution, keeping world
and preview anchors separate. First person continues using the camera quaternion.

Native submission uses Blaze3D buffers, binding layouts and render passes. Optional Iris
mixins are disabled without Iris; native pipeline construction does not enter its OpenGL bridge.
Resident geometry and index revision reuse remain; adjacent equal-state legacy batches merge.
Iris geometry expands authored triangle corners once during GPU upload so its BufferBuilder can generate tangents/mid-UV. The resident vertex buffer is reused with expanded source/mirrored/sorted indices. Shader enable/disable and pipeline recreation invalidate both caches. Upload failures retain the completed-frame CPU fallback.

## Inventory first-frame correction

User noticed survival inventory initially feeding the halo an incorrect pose, also seen on the old 1.20.1 adapter. Minecraft 26.2 `InventoryScreen.extractRenderState` updates xMouse/yMouse only after superclass background extraction. The new `InventoryPreviewMouseMixin` sets these from current background arguments before model extraction when Halo preview is enabled. The vanilla model and Halo therefore initialize from the same current mouse position; no core change or low-version API adaptation is required. Build passed (`halo-262-preview-fix-build.log`); user confirmed repeated survival inventory opens, ordinary pointer following and world rendering are correct in `halo-262-preview-final.log`; client exited cleanly.
