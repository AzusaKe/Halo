## 修复行为

旧实现每帧根据录像的 UI 状态重新创建权杖屏幕，手动关闭后立即重新打开，导致 ReplayMod 操作被屏幕占用。本次只修改 Halo 客户端显示策略：

- `config/halo-azusake/halo_mod_config.json` 新增 `replayScepterUiEnabled`，默认 `false`，缺少字段自动补齐。只有 JSON 布尔值 `true` 启用；非法类型回落并修复为 `false`。普通配置保存保留该字段和其他未知配置。
- 默认不显示回放权杖 UI，录像里的 UI 开关状态仍完整记录、恢复和推进。普通游玩的权杖界面照常显示和关闭。
- 显式启用后显示只读 UI，播放与暂停时均可用 ESC／关闭按钮退出。当前录制 UI 会话被本地抑制，恢复播放不会再次弹出；下一次录制的打开事件可以显示新会话。
- seek 的新 epoch 重新判定目标位置，允许恢复该时刻的 UI。恢复过程的中间快照不弹屏；同 epoch 的快照补齐不撤销手动关闭。
- 导出准备／导出始终不创建交互屏幕，自动移除 UI 不等同于用户手动关闭。只处理回放权杖屏幕，不主动关闭普通权杖或覆盖其他屏幕。
- UI 抑制状态只在 Halo 适配层，配置字段由适配层存储读取；core 配置 DTO、源码、版本、gitlink、API v2、录像 schema 都不变。现有录像无需重录。

配置示例（把字段加入现有 JSON 对象，不覆盖其他设置）：

```json
"replayScepterUiEnabled": true
```

此配置沿用现有初始化加载方式，编辑后重启客户端生效；没有新增热重载指令。

## 游戏验收步骤

每次只安装一个录制模组，替换旧 Halo JAR。优先使用已有包含权杖打开／关闭的录像，对照先前发生输入锁定的片段。

1. 保持默认 `false`，依次测试 ReplayMod 和 Flashback：回放经过 UI 打开区间，确认没有权杖屏幕，回放按钮、暂停、时间轴和快捷键正常；暂停、倍速、前后 seek、重复打开均正常。
2. 正常进入游戏打开并关闭权杖，确认普通 UI 未被隐藏。录制一次包含 UI 开关的新录像，保持相同资源和配置。
3. 退出客户端，将字段改成 `true`，重启并打开录像：记录的打开区间显示只读 UI。分别在播放和暂停时使用 ESC／关闭按钮退出，确认不会立即重开，恢复播放后仍不重开，ReplayMod 控件和快捷键可用。
4. 继续到下一次录制的 UI 打开／关闭事件，确认新会话正常显示并在记录的时刻关闭。向前／向后 seek 到打开区间应按目标位置重新显示；seek 到关闭区间应隐藏。ReplayMod 分别检查 Full 和 Quick。
5. 在配置为 `true`、逻辑 UI 打开的时刻准备导出，检查不会出现权杖屏幕阻塞；导出、取消、重新导出及回到回放后均能操作。UI 选择／关闭不向服务器写回，关闭不改变录像数据。
6. 使用旧录像时，原本缺失的 UI 关闭事件仍无法补录，但默认隐藏和手动关闭也应防止界面锁定。Iris、YSM、多视角等未测组合继续标为未验证。
