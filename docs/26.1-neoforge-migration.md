## Validation and release gates

Run standalone core and combined build, frozen API callers and flat distribution checks. Use the official YSM hotfix via `HALO_YSM_TEST_JAR`; report any missing-fixture skip explicitly. Test native first, then EMF/ETF, YSM, Iris/Sodium; exact versions are pinned in the compatibility manifest.

Use isolated worlds. The user assists visual/input checks and owns network testing. Prepare a fixed candidate and SHA-256 before handoff. No tag before functional, visual, network and pressure-test acceptance.

Performance: Mika OBJ (~96,484 faces), 1/8/16 instances, fixed camera/world/resolution, IterationRP Alpha 0.8.22. Bliss was explicitly removed from scope by the user on 2026-09-20 due to poor support for this game version. Warm up 60 seconds and collect 120 seconds per run, three repetitions; A/A before cached/expanded A/B. Record frame percentiles separately from Halo CPU submission and upload counters. No claimed FPS gain before measurement.

Core commits, if necessary, must be backward-compatible, tested with frozen callers and the development mainline, then committed/pushed before the Halo gitlink. Final release requires clean repositories, exact provenance, target branch CI and verified Release artifacts. This task develops directly on the requested Halo branch; temporary core branches must be integrated and removed.

## Candidate 06 regression and candidate 07 correction

- User rejected candidate 06: world halos were invisible with shaders both enabled and disabled. Startup success and capture logs did not establish successful drawing.
- Root cause: the new world-frame guard was reset at `GameRenderer.render` HEAD, after 26.1 had already fired `ExtractLevelRenderStateEvent` during `GameRenderer.extract`. The solid-stage callback therefore saw no captured frame and skipped drawing.
- Candidate 07 starts the world frame at `GameRenderer.extract` HEAD; GUI preview session begin/end remains around drawing. A compiled Mixin contract test verifies that the world reset runs before extraction and is absent from preview begin. Existing gate tests still cover shadow/repeated-stage rejection.
- `build-07.log` passes (132 platform + 326 core tests). SHA-256: `d3deca7990ce8033e2dc531d405b80102c8fdd1b9642d4743e921529577905c9`; mod manifest `evidence/compat-candidate-07.json`. Screenshot inspection confirms world ring/mesh and the GUI preview visible again. Shader toggle recompiles the four private material programs and selects the Halo pipeline. User visual retest remains pending.
- Candidate 06 server persist/recover was rerun successfully after its storage changes. Candidate 07 only changes the client frame lifecycle and its regression test; network acceptance remains pending.
- The compatibility run has `halo.mesh.profile=true`, with GL diagnostics disabled. Mixed-fixture counters prove drawing resumes; they are not the planned controlled A/A or A/B benchmark and are not an FPS claim.

## Final approval and Fabric save-compatibility correction (2026-09-20)

The user accepted network and persistence and explicitly approved the version for release, conditional on importing the new Fabric repair. Reference: `26.1-fabric@5cc5d866870e7c839cec30b8d680162fc669e9c1`. No other subsequent Fabric changes were imported.

Reading flash UUID integer arrays was insufficient while the new adapter continued writing strings. The branch now restores the structured SavedData Codec with `UUIDUtil.LENIENT_CODEC` input and canonical UUID integer-array output, `halo:world_data`, `Halos`/`UUID`/`Definition`, and `SAVED_DATA_MAP_DATA`. Its existing legacy-file import remains intact and does not resurrect entries when a current empty file exists. Core, entity NBT, networking and rendering are unchanged by this correction.

`build-09-save-compat.log` passes: **136 platform + 326 core tests**, zero failures/errors/skips. Tests cover flash arrays, affected strings, multiple/mixed entries, empty data, descriptor/fix type, load-modify-save, strict flash UUID decoding, removal and legacy import. Flat-JAR and frozen API v2 checks also pass.

The official NeoForge dedicated server restored armor stand `591566c1-67d1-40e9-a661-34e18109e0b7` with `halo:mesh_mask_demo` after restart. Independent decoding of the real saved file confirms UUID NBT tag **11 (integer array)**. Evidence: `evidence/save-compat-persist.json`, `smoke-persist.log`, `smoke-recover.log`. The dimension-relative data path is `halo-smoke/dimensions/minecraft/overworld/data/halo/world_data.dat`.

Candidate 09 only changes `HaloWorldSaveData` and its nested record class relative to accepted candidate 08; bytewise comparison finds no rendering/network class changes. The sealed JAR and hash are under `candidates/09`.

The user's release approval closes the previous pending acceptance gates.
