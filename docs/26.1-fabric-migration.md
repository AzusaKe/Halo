## 2026-09-19 rendering regression fixes

The user reported: transparent mesh faces were obscured by clouds without shaders and almost
invisible against the sky with IterationRP; the scepter item model was missing; smooth normals
were lost under IterationRP. After restarting with these fixes, the user confirmed all three
reported problems had disappeared. This confirmation applies to this scene and combination,
not to the complete migration acceptance matrix.

- Deferred meshes now draw after `FrameGraphBuilder.execute`, after clouds/weather and vanilla
  transparency resolve, before Iris composites and the world camera transform is removed.
  Core is not advanced again in this hook; per-instance and per-triangle view-depth sorting remains.
- The scepter has the native `assets/halo/items/halo_scepter.json` model entry, referencing the
  existing item model and texture. Held appearance was also observed by the agent.
- Halo wraps native/Iris pipeline selection so its cloned programs cannot be bypassed by another
  HEAD injection's early return. Lit clones use entity solid/translucent programs. Fullbright
  clones use the original adapter's particles semantics, linked against Halo's entity vertex layout.
- The generic derivative normal pattern matched both lit variants of IterationRP Alpha 0.8.28.
  Logs confirm private-program selection during drawing, not only shader compilation.
- HaloMask reserves texture unit 3 only inside private shader construction. Native samplers remain
  on 0/1/2 even when unused uniforms are optimized out; Iris allocates PBR samplers around the
  reserved mask unit. Other Iris programs remain unchanged.
- The normal patch requires a matching vertex ABI. Unrecognized normal reconstruction remains
  unchanged; the code has no shader-pack name check. Temporary absolute-path shader dumps removed.

Evidence: `F:/codex-cache/halo-261-render-fixes-client.log`,
`F:/codex-cache/halo-261-render-fixes-build.log`, and isolated client screenshots
`2026-09-19_17.17.00.png` (IterationRP, scepter) / `2026-09-19_17.19.01.png` (no shaders).
Exact runtime: Minecraft 26.1.2, Loader 0.19.3, Fabric API 0.155.3+26.1.2,
Iris 1.11.4+mc26.1.2, Sodium 0.9.2+mc26.1.2, EMF 3.3.8, ETF 7.2.4.
The latest shader whitespace/vertex-ABI guard is additionally covered by platform tests.

## 2026-09-19 shader composite depth fix and user acceptance

The user subsequently reproduced sky occlusion in Bliss v2.1.2 and grass showing through
opaque mask regions in IterationRP Alpha 0.8.22. Iris's entity/particle composite programs
need the nearest surviving surface depth as well as color. Halo now enables depth writes
for depth-tested world draws while a shader pack is active; native and GUI depth semantics
remain unchanged. Instance/triangle sorting and mask discard remain in place. This is an
adapter-side Iris depth contract; no core material rules or public API changed.

The isolated Bliss run built successfully (`F:/codex-cache/halo-261-depth-bliss.log`).
Two policy regression tests cover Iris/native/GUI behavior and authored depth writes.
The user then completed testing, confirmed the bugs disappeared and requested release.
This records user acceptance of the reported defects, not an assertion of all shader packs,
LabPBR channels or all three game versions having been visually tested.
