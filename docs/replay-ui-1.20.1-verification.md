## UI 行为与配置

`config/halo-azusake/halo_mod_config.json` 增加 `replayScepterUiEnabled`，默认 `false`；缺少字段自动补齐，只有 JSON 布尔值 `true` 开启，其他类型修复为 `false`。未知字段与普通 core 配置保存保持兼容。编辑后重启客户端生效，没有新增热重载指令。

默认只隐藏回放权杖屏幕，仍记录、恢复和消费 UI 轨道。普通游玩的权杖照常使用。显式开启时，回放 UI 为只读，播放和暂停都可通过 ESC／按钮退出；当前录制会话不会立即重新弹出，恢复播放也不重开。下一次录制的打开事件可显示新会话；seek 的新 epoch 按目标位置重新判定，同 epoch 快照补齐不会撤销手动关闭。导出准备／导出始终隐藏，不覆盖录制器进度或错误屏幕。

把以下字段加入原 JSON 对象，不覆盖原有其他配置：

```json
"replayScepterUiEnabled": true
```

关闭屏幕只修改适配层本地显示抑制，不修改录像 UI 轨道、不发送 C2S 或递归录制。已验收的五个共享策略／配置源码和测试文件逐项对照 1.21.1 原始交付源码哈希一致（文本换行等价）；1.20.1 的屏幕只追加必要回调，没有整类覆盖或整分支合并。

## 游戏测试步骤

先用独立 1.20.1 实例，只装本次 Halo、Fabric API 和固定 ReplayMod 2.6.28；固定资源包、定义、模型及配置。再单独替换为 2.6.23 复查，不同时安装两份 ReplayMod。

1. 配置保持默认 `false`，打开包含权杖 UI 区间的既有录像：经过打开／关闭时刻、暂停、恢复、倍速、前后 seek 和重复打开时，不弹出权杖屏幕，ReplayMod 按钮、时间轴与快捷键可正常使用。
2. 普通游戏中打开权杖，分别 ESC／按钮关闭，确认功能正常。录制新片段：起点已佩戴、启动／关闭中间态、移动转头、摘除再佩戴，并至少两次打开和关闭权杖。
3. 退出游戏，把配置改为 `true` 后重启。回放显示只读 UI；分别在播放和暂停时 ESC／按钮关闭，确认不会立即重开、恢复播放不重开，回放控件恢复。下一次记录的打开可显示新会话，并在记录时刻关闭。前后 seek 到 UI 区间按目标状态恢复。Full／Quick 及互切分别检查。
4. 测试 0.5×／1×／2×、连续跨多个周期快照、前后 seek、反复打开录像。动画按源时间推进，暂停冻结，连续播放无周期 snap；seek 清除未来惯性并恢复目标相位。
5. 从非零起点分别导出 30／60 FPS，覆盖 2× 时间关键帧、UI 配置开／关和逻辑 UI 打开区间；确认一秒源动作仍推进一秒 Halo 表现、无权杖屏幕阻塞。检查取消、重启和返回回放后仍可操作，没有 C2S 写回或递归录制。
6. 复查录制暂停／恢复、marker 裁剪／拆分；新片段起点的佩戴、相位和 UI 正确。补测本地模式、Halo 专用服双客户端、来源切换／回退、空佩戴快照、健康实体卸载返回、换维度／重连。
7. 多视角、Iris/LabPBR、EMF/YSM 分别记录实际版本和结果；未测项仍为未验证，不从 1.21.1 推定通过。
