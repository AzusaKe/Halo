## 实现与契约

- 多个 OBJ draw 的一次提交共用 `MeshDrawWorkspace`，逐元素读取不可变命令的矩阵，保持原来的矩阵乘法、法线逆转置及奇异矩阵回退。单 draw 保留原矩阵/材质准备路径，避免创建没有复用机会的缓存；世界早期、延迟和 GUI 提交分别拥有暂存对象。
- core 的 `MeshIndexWriter.prepareBackToFront(MeshDraw)` 返回 writer 内局部修订号，仅当深度矩阵的 2/6/10/14 四项逐位相等时复用。平移参与 key，重算总是产生新修订号，不能当作索引内容 hash。原有写入入口、算术、稳定排序和镜像绕序保持不变；源序写入不修改排序工作区。
- 适配器的 flat/lit 动态 EBO 各自记录实际上传的修订号与镜像状态。命中仍重新绑定正确 EBO，只省去 CPU 索引写入与 `glBufferData`。准备排序不会更新上传记录；上传返回后才更新。新 writer/EBO 必须使用新记录，沿用既有资源代次、模型身份及 Iris 格式重建生命周期。
- `HaloMeshShader.Submission` 只缓存当前调用的程序、uniform 句柄与纹理对象查找结果。实际 shader、纹理槽、光照/遮罩/颜色/法线、混合/剔除/深度设置和 shader apply/clear 每次 draw 照常执行；CPU fallback 后失效缓存。
- 原生/Iris 分流、Iris 不透明受光提前提交、透明深度修复、GUI 上下文、几何和命令顺序不变。没有 LOD、裁剪、材质重排、实例化或新顶点格式。
- 版本特异逻辑只在适配器；core 保持 Java 17 与原依赖。定义 JSON、存档、协议、API v2、已有构造器和 writer 方法均不变，旧适配器无需调用新增方法。冻结 flash 分支不修改。

## 游戏探针与证据

独立验证目录：`F:/codex-cache/halo-mesh-optimization/`。使用既有测试实例的独立副本，不向用户原实例写入模组、配置或世界。
`baseline-halo.jar` 的构建来源与上述两个基线 SHA 一致；每轮 `inputs.json` 保存运行参数、Halo/探针/模组 SHA-256。不同候选/探针版本的数据不得混作同一配对。

探针计时覆盖 `renderHalos`、`submitDeferredMeshes` 与 `submitPreview`，嵌套调用不重复计时。实际 VBO draw、稳定排序和动态 EBO 上传分别计数。相机/平台/实体/佩戴/可见性、实际窗口与主/Iris framebuffer 尺寸、资源代次和 pipeline 都有断言；OBJ 场景另核对实际提交数量。截图和 CSV 写入在采样窗外。

v4 视觉探针另外定期读取当前绑定的实际 GPU EBO，与独立冻结的 2.3.1 writer 对同一命令生成的普通/展开、源序/透明排序及镜像索引逐整数比较。性能模式关闭此读回与参照计算，不把诊断开销计入 A/B。

夹具包括零 mesh、单个低面数 flat/lit、单个高面数（32,768 三角形）、大量同模型、交替材质、多模型、透明持续命中/未命中、flat/lit 透明混用，以及原有六个 billboard/ring 场景。材质覆盖 LINEAR/STEP 遮罩、镜像和零缩放。后续资源修改对应新探针 SHA。

分辨率/全屏切换后，先等待窗口与主 framebuffer 达到目标尺寸并稳定至少 2 秒，再重载光影，随后等待至少 2 秒并核对 Iris targets。BSL、IterationRP（以及 Bliss）统一走此流程；视觉与性能探针共用该准备步骤，正式预热/采样在其后开始。用户确认 IterationRP 也存在切换全屏后的 LOD 覆盖地形现象，不能仅以 `glError=0` 判断场景有效。

旧视觉探针在切换全屏的同一个 tick 立即重载，时机过早。`evidence-visual-iteration-4k` 及采用同一流程的 `evidence-visual-bliss-4k` 已加 `INVALIDATED.md`，保留原始证据但排除出分析和准入；后者是保守排除，不表示已确认 Bliss 出现相同问题。重跑必须使用新的证据目录和探针指纹。

运行器 `suite.py --prefix <唯一批次名>` 固定输入指纹、检查已完成单元并支持续跑；输入变化或残留未完成单元会停止。`analyze.py --prefix <批次名>` 汇总逐轮整帧/完整 Halo CPU 的 P50/P95/P99、转回 200ms 峰值、分配、排序、提交和上传量。JFR、截图、原始 CSV 和窗口起止时间一并保留。

v4 专项的探针已另存为 `probe-index-v4.jar`，后续 v5 增加视觉上传失败/恢复检查，二者不混用配对数据。

未完成项单独保留：除原生 1080p 透明静态命中场景外，其余场景/分辨率/光影组合尚未完成本轮 A/A + 五组 A/B；原生 4K、Iris 安装但关闭光影的两种分辨率、IterationRP/Bliss 1080p 尚未执行本候选的相应矩阵。三个优化各自的独立性能归因、光影同时间历史像素对照、实际 EMF 模型及加载/重载/首次入镜的配对耗时也未完成。历史版本结果不补记为本候选通过，短程排错不充当正式准入。

任一组合出现可复现退化则该项不得进入默认实现，不能以其他场景收益抵消。波动未收敛、缺少 A/A 或不足五组配对均为未验收。正式视觉验证还需同输入/时间历史的基线对照、GUI/EMF/YSM、光影切换、资源重载/失败回退，以及加载与首次入镜数据。
